## Finding: B32 (1.0.2 cannot auto-update)

1.0.2's `Update_Checker::normalize_install_source_dir()` compares the unpacked folder with a trailing slash against the same path without one. They never match, so it deletes the correctly named folder and WordPress reports "A directory could not be read". The bug is in 1.0.2, so it cannot be fixed by a new release.

**Recommendation (owner decision):** update each managed 1.0.2 site once by uploading the 1.0.3 ZIP (Plugins → Add New → Upload Plugin → Replace current with uploaded), then purge the page cache. From 1.0.3 on, updates are automatic.

**Optional workaround (not done):** attach a second asset named like `landing-page-manager-pro-legacy.zip` whose top folder has a different name, uploaded before the main asset. 1.0.2 picks the first matching asset and its folder rename would then succeed, while 1.0.3+ installs only `landing-page-manager-pro.zip`. This edits a published release and breaks the one-folder packaging rule for that asset, so it is not recommended while all sites are managed.
